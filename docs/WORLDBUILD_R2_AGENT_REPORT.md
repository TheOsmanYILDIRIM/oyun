## Contract for downstream agent D and coordinator
- `Features.new(validated_v1_authored_map)` snapshots immutable-identity feature polylines (world units); `:nearest(x,y,"water"|"path")`, `:signed(x,y,kind)`, `:at(x,y,kind)`, `:intersections()`, `:crossing_site_status(site)`, `:resolve_crossings(sites,crossing_definitions,max_depth,ford_max_depth)`. Canonical Python A-v1 and global-v2 validation **must still be executed by the loader**: this runtime adapter is not a substitute for complete source-schema validation.
- `Routes.new(baseWorldQuery, features, {topography=B_surface, sites=..., crossings=..., water_max_depth=..., ford_max_depth=..., path_cost_factor=..., route_stride=...})`; B surface requires `:height(x,y)` and `:transition(x1,y1,x2,y2)`. Input is opt-in, with matching `seed` and `generator_version=1`; tests load the actual B branch module by an exact-blob check, not a synthetic substitute.
- Runtime query facade: `:water_mask(x,y) -> is_water,signed_field`; `:surface_at(x,y) -> {id,speed_multiplier,immersion,water_body,wet,water_depth,water_feature_id,path_feature_id,crossing_id,crossing_kind,current}`; `:sample(x,y)` and `field:channel(x,y,"water")` share the same authoritative signed water membership (positive is wet). Nonwater fields and unaffected generator points delegate. Additional `:get_feature`, `:get_biome`, `:get_height`, `:is_walkable`, `:get_obstacles` delegate or reflect the facade. `:route_cost({x,y},{x,y}) -> {walkable,cost,length?,reason}`, using the actual B transition, slow-water cost and dry-path preference. `:flow_report()` and `:crossing_diagnostics(sites)` expose incompatibilities.
- **Water physics preservation:** wet traversal still `speed_multiplier=0.55` and `immersion=0.5`. A bridge is dry for traversing/immersion but remains a water-body mask underneath for downstream terrain/render; a ford remains wet. A bridge must intersect both real centerlines at an explicitly designated crossing site, have adequate bank-to-bank span and path-compatible width. Nearly parallel paths, short bridges and deep declared fords are rejected.
- Authored depth is deeper at center, shallower at banks; provisional `water_max_depth=2` world units, `ford_max_depth=0.75`, `path_cost_factor=0.85`, route sampling 2 units. These are tuning defaults, **not approved permanent gameplay balance**. Generator-v1 water depth/flow remains **unknown** rather than fabricated. Flow direction is derived from B elevation; no current velocity, erosion, seasons or physical riverbed sculpting are simulated.
- Do not insert this facade in `main.lua` or ship it as a fully activated WorldQuery without downstream mesh, collision/player, navigation, ecology/build and Stage5/6 save parity checks. Height slope obstruction is evaluated in `:route_cost`; `:get_obstacles` deliberately does not silently change physics.

An independently intersecting path feature without a matching validated crossing site is **not** permission to create a bridge.
- **Required coordinator/A-data action before physical crossing activation:** explicitly correct/author an A-owned water/path alignment and crossing-site anchor, validate stream/route/connector continuity and immutable IDs with v1+v2 validators, then pass an opt-in real crossing definition through D's integration. C does **not** edit A's authored JSON, connector graph or site IDs.
- A-source water segment elevation checked against real B topography reports **consistent downhill** for this authored stream in the tested fixture. This is no proof of future dynamic hydraulic flow.
